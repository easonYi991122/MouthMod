# 头部视角通道：暂定实现选择

V5 规格（[E] §4–5、[Z] §6）冻结的部分：α ≈ 0.98；死区 ±3°；迟滞 2°；饱和 ±20°；`dx = kx·(roll−roll0)`，`dy = ky·(pitch−pitch0)`；k 左右和上下分开设；不积分偏航；校准时静止 3 s；回中 300 ms 后自动进入 ACTIVE；主循环 100 Hz 非阻塞。
下表列的是规格没写或交接指南明确要求「不能编造冻结值」的项目。这里给出的都只是**暂定值**，实测后要更新，并在组内确认。

| # | 项目 | 当前选择 | 依据 / 怎么改 |
|---|---|---|---|
| D1 | 死区与迟滞的组合公式 | 默认 `hmode=0`（内收）：\|e\| ≥ 3° 开始转，\|e\| < 1° 才停；可切换为 `hmode=1`（外扩）：≥ 5° 开始转，< 3° 停 | 交接指南 §b 标为待确认；两种都实现了并有测试，用测试页比较后由组内定 |
| D2 | 刚越过死区时速度是否跳变 | 默认 `vmode=0`，按规格原式 v = k·e（越过 3° 时直接从 0 跳到 3k）；可切换 `vmode=1` 斜坡式 v = k·(\|e\|−出界角)，速度从接近 0 开始 | 规格要求「小倾角慢转」，两种都满足；建议在测试页上对比手感 |
| D3 | k 的单位 | HID 计数 / 秒 / 度。按真实 dt 换算成整数增量，小数部分留到下次 | 交接指南要求「先明确 k 的时间单位」 |
| D4 | k 默认值 | kx = 40，ky = 30（暂定）。在 MC Java 100% 灵敏度（0.15°/计数）下，倾 10° 约 60°/s，倾 20° 约 120°/s | 按人调，记录在评估元数据中 |
| D5 | 静止判据 | 3 s 窗口内：每轴陀螺标准差 ≤ 3.0 dps（原定 1.0，2026-10-16 实板拿在手上测得 1.30/1.95/1.11，每次都 `fail_motion`）；加速度均值的模长在 0.9–1.1 g；新样本 ≥ 250 个（104 Hz × 3 s 的 80%） | 规格没给；用实测静坐佩戴时的噪声来校正 |
| D6 | 校准失败的去向 | 回到 DISARMED，并报告原因（`fail_motion / fail_samples / fail_accel`），需要重新发起启用 | 不自动重试，免得「一直校准」掩盖问题 |
| D7 | 回中判据 | roll 和 pitch 误差都小于开始转动的角度（engage 边界），连续 300 ms | 和映射器保持一致：回中区内一定不输出 |
| D8 | IMU 超时 | 100 ms 没有新样本 → FAULT；启动宽限期同为 100 ms | 规格没给；按 104 Hz 计相当于丢了约 10 个样本 |
| D9 | α 与采样间隔 | α 按 10 ms 的标称步长换算成时间常数 τ = α·0.01/(1−α) ≈ 0.49 s，每个样本按真实 dt 混合；间隔 > 100 ms 时用加速度计重新初始化 | 不能把 HID 发送间隔当成 IMU 采样间隔 |
| D10 | 加速度计参与条件 | 模长在 0.7–1.3 g 时才用加速度计修正，否则这一步只用陀螺 | 抑制头部快速运动引入的线加速度 |
| D11 | 积压上限 | 每轴待发计数最多 ±64；端点阻塞时多出的部分丢弃 | 交接指南要求「不要积攒陈旧相机移动」 |
| D12 | IMU 配置 | ODR 104 Hz，±2 g，±245 dps，不用 FIFO；I2C 400 kHz；先查 STATUS_REG 的 XLDA 和 GDA 位，再一次读出 12 字节 | 交接指南 §f 的建议值；如果实测饱和，记录下来再改 |
| D13 | 安装方向 | 由「朝上轴 + 朝前轴」确定，24 种组合都支持，默认 `+Z/+X`。头部坐标系：x 前、y 左、z 上；roll 正 = 右耳向下，pitch 正 = 低头 | 装到头带上后实测确定，确定后写入 Config.h |
| D14 | 陀螺零偏存放 | 存头部坐标系下的值；修改安装方向会清掉零偏并停用 | 避免拿旧零偏去配新安装方向 |
| D15 | 调试版专用 | 用串口 `arm` 代替长吸启用，`ack` 代替 D6 拨动；DTR 断开即停用；HID 默认关闭；不启动看门狗；`act`/`tap`/`turn` 只能在 ACTIVE 时使用，用来替代还没接上的通道 | 并入完整固件时，改为接 SafetyStateMachine 的吸气和 D6 逻辑，删掉这些串口动作命令 |
| D16 | Space / 右键最短按住 | 60 ms，从报告被端点接受时开始计时；停用时立即松开，不受这个限制 | 比一个 50 ms 游戏 tick 长；用 `tap jump` ×20 实测，见 docs/minecraft-education.md |
| D17 | 键盘与鼠标共用端点 | 每循环只发一个报告；两种报告都有数据时轮流发送；每个鼠标报告都带当前按钮状态 | 交接指南 §HID「公平调度」；最坏情况下视角每 20 ms 更新一次，需要实测延迟 |
| D19 | 摇杆跨度 | 默认按电位器名义半程 1877 counts（12 位、3.6 V 量程、3.3 V 供电）归一化；`jspan` 记录每人四个方向的舒适极限后替换 | 规格要求按舒适行程归一化，不能把满量程端点当作舒适范围；具体数值写入记录 |
| D20 | 摇杆中心 | 在启用后的 3 s 静止窗口内取均值；窗口内波动超过 0.08×跨度就判失败（`fail_joystick_center`）并停用 | 「每次佩戴重置旧结果」 |
| D21 | 压力阈值 | 吹气沿用组员实测的 120000/50000 counts 和 250 ms 释放延迟；吸气暂取对称值；符号 `bsign` 默认为 +1，必须实测 | 规格没有给压力阈值的绝对值；原代码用的是绝对值，吸气也会触发，已改为带符号 |
| D22 | 压力基线 | 启用后丢弃前 5 个样本，再取 25 个样本的均值作为基线（种子样本饱和就重新采）；之后在 \|p\| < 0.3×触发阈值时，按 τ=10 s 慢速跟踪 | 原代码按 delta/128 跟踪（40 Hz 下 τ≈3 s）；规格要求 τ≈10 s，并且偏离超过 0.3× 阈值时冻结 |
| D23 | 压力超时 | 启用后 1 s 宽限期；之后超过 250 ms 没有新样本 → FAULT；OUT 引脚上拉，模块没接时也会超时 | 原代码是 350 ms 后只松开按键；规格要求传感器超时进入 FAULT |
| D24 | 吹气按键 | 右键，吹气期间按住（规格冻结）；没有移植原代码的左键自动连击 | 组内要改的话需明确决定，改 `mc::kButtonUse` 即可 |
| D25 | 长吸启用 | DISARMED + D6 闭合 + 吸气 ≥ 1 s → 开始校准。这口吸气必须是在 DISARMED 下开始的：从其他状态进入 DISARMED 后，要先看到吸气电平松开，才接受新的长吸。是否松开按吸气迟滞后的电平判断，不按计时器判断。长吸启用时保留已跟踪的吹吸基线，不用吸气时的压力重新采基线。串口 `arm` 保留作为调试备用 | 交接指南「连吸与重新启用」建议的实现补充；调试版因为 DTR 停用，还需要串口打开 |
| D26 | 看门狗 | nRF52 硬件 WDT 500 ms，只在主循环的传感器校验之后喂狗；`#I` 上报复位原因；用 `hang` 命令注入卡死来测试。**默认不启动** | 先确认 WDT 运行时上传和双击 RESET 进入 DFU 仍然正常，再在 Config.h 里打开 |
| D27 | 视角起转区间 | 起转角从 3° 加大到 6°，停转角为 4°（迟滞 2°）；越过起转角后要保持 80 ms 才开始转；速度改用斜坡式（vmode=1），从停转角起由 0 增加 | 2026-10-20 组内反馈「轻微扰动就开始移动」；规格里 3° 本来就只是可调起点。`set dead/confirm/vmode` 可调，单文件版同步修改 |
| D28 | 只对 Minecraft 生效 | 板子无法知道前台窗口，所以由 bridge.py 每 250 ms 用 `lsappinfo` 检测前台应用（不需要额外权限）。Minecraft 在前台时每 250 ms 发一次 `focus 1`；板子 0.7 s 内没收到就视为不在前台，并松开所有按键。只有 `fgate 1` 且真实 HID 打开时才起作用 | 桥挂掉也会停止输出（失效即安全）；目前只支持 macOS |
| D29 | 吹气按键（取代 D24） | 吹气改为**左键**，吹气期间按住，最短 60 ms；不做自动连击 | 2026-10-20 组内实测后决定：玩法需要攻击/挖掘。按住左键可以连续挖方块；要像原代码那样每 600 ms 连击，需要另外决定 |
| D30 | 上电默认打开真实输出 | `kHidEnabledAtBoot = true`；页面关闭、Esc、停用按钮只停用，不再关 HID | 组内反馈每次都要勾选很麻烦。安全性靠：上电是停用状态，启用要长吸或点按钮，并经过 3 s 校准和回中；有桥时还有前台门控 |
| D31 | 吹气回弹不算吸气 | 吹气按住期间（含 250 ms 释放延迟），以及释放后 400 ms（`set slock`）内，不判定吸气 | 实测用力吹到约 +3000000 后会回弹到约 −190000，持续约 150～300 ms，被误判为吸气而停用（日志里是 `sip_disarm`）。主机测试已覆盖 |
| D32 | 悬浮窗 app（方案 B） | 用 macOS 原生的非激活置顶面板（NSPanel）显示 `float.html`；app 在空闲端口上自己启动 `bridge.py`，退出时停用板子。点击面板不会让 app 成为前台；只有输入框获得焦点时才临时接管键盘，按回车、Esc 或离开输入框后交还。Chrome 画中画方案保留作为备用 | 原方案要先开终端、再开浏览器、手动处理端口；而且点击悬浮窗会让 Chrome 成为前台，前台门控因此拦截输出。新方案界面仍只有一份；整个 app 约 0.4 MB，只依赖系统组件 |
| D33 | 面板灵活性（v0.7.0） | 视角左右、上下各自选择来源（侧倾 / 俯仰 / 转头 yaw；yaw 用陀螺积分，按 `yawtau` 回零），可分别取反，起转角分轴（`deadx/deady`）；摇杆按轴分别设置触发和释放阈值；全部参数都能在悬浮窗调整页修改 | 组内要求按个人和装法灵活适配。yaw 没有绝对参考，标为实验功能 |
| D34 | 吸气 → 跳跃 | 每次吸气（吸气电平的上升沿）点按一次 Space，与咬合并用（`sjump`）；吸气停用改为按住 ≥1.5 s（`sdis`，0 = 关闭）；停用状态下长吸 ≥1 s 启用不变 | 组内决定吸气用于跳跃。原来 150 ms 的吸气停用会让跳跃无法实现 |
| D35 | 吹气模式 | `pmode` 0 = 按住（默认，同 v0.6.1），1 = 吹一下切换，2 = 连点（`prep` 默认 600 ms，与组员原代码一致） | 有人反馈「不能一直砍」。排查固件：吹气期间左键一直按住，每个鼠标报告都带着按键状态，没有发现会中途松开的缺陷。可能原因：Minecraft 里按住左键不会连续攻击生物；或吹久了气压掉到释放阈值以下。因此提供模式切换，并在面板开放阈值和释放延迟 |
| D36 | 参数保存 | 面板「保存为默认」写入 `~/.mouthmod/profile.txt`，桥在每次串口连接 1.5 s 后回放；只接受 `set/chan/mount/fgate/hid` 开头的行 | 固件参数断电即失；先在电脑端保存，暂不改固件 flash |
| D37 | 加速度+角速度融合（v0.8.0） | `fuse 1`：用欧拉角运动学积分陀螺；从加速度里减去力臂项 α×r + ω×(ω×r)（r = (armx, 0, armz)，α 为 20 ms 低通的角速度导数）得到重力；按偏离 1 g 的程度（`arej`）降低加速度信任；输出线加速度估计（`F` 行）。yaw 改为绕重力竖直轴的航向，仍按 `yawtau` 回零。默认 `fuse 0`，与 v0.7.0 完全一致 | IMU 改放到嘴前，离转动中心约 10 cm，转头的切向加速度可达 0.2 g 以上，会被基础滤波当成侧倾。六轴没有磁力计，yaw 只能靠陀螺，没有绝对参考。调研见 docs/imu-fusion-survey.md：之后可评估改用 x-io Fusion（MIT） |
| D38 | 视角控制方式 | `lmode` 0 = 倾角速率控制（默认），1 = 角速度直接移动（空中鼠标），2 = 两者相加；角速度项 = kg ×（来源角速度 − gdead），每轴限幅 4000 计数/s；起转、回中仍按倾角判断 | 倾角控制能持续转身，角速度控制响应快、适合精确瞄准；混合方式参考了 JoyShockMapper 的 Motion Stick + Gyro Mouse |
| D39 | 五点精细校准 | 记录中立、左转、右转、低头、抬头五个姿势（各取 500 ms 平均，晃动超过 4° 作废）；roll/pitch 存绝对角，yaw 相对中立；启用时检查每轴两侧至少 3° 且方向相反，自动挑变化最大的来源（`fauto`）；映射为两侧分别线性缩放，到记录姿势时等于 `sat`。基础校准仍负责陀螺零偏和静止检查 | 使用者不一定坐在中立位，左右可转幅度也可能不对称。没有找到现成的五姿态流程，参考了 opentrack 的正负方向曲线和 RC HeadTracker 的 center/min/max |
| D18 | USB 重新枚举 / 唤醒 | 视为主机状态未知：先发中立报告，并停用（DISARMED） | 交接指南 §HID「重连先发中立报告并保持 DISARMED」 |
