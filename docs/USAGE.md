# MouthMod 接线与使用说明（v0.8.1）

2026-10-28 · 固件 `MouthMod-ImuBench 0.8.1` · 板子 Seeed XIAO nRF52840 Sense

一句话概括：所有传感器都接到同一块 XIAO 上，这块板通过 USB 直接充当键盘和鼠标。电脑上运行一个本地桥 `bridge.py`，负责显示状态、调参，并且只在 Minecraft 位于前台时放行输出。

> 状态说明：本文所有功能都已编译，并通过了主机端测试。前台门控和悬浮窗在模拟板上跑通了。**接上真实传感器后的效果、在 Minecraft 里的实际表现，都还没有验证**，以今晚的实测为准（测试表见 [minecraft-education.md](minecraft-education.md) 第 5 节）。

## 1. 接线

### 1.1 引脚表（规格冻结，不要改）

| XIAO 引脚 | 接什么 | 说明 | 固件现状 |
|---|---|---|---|
| A0 / D0 | 摇杆 X 电位器的**滑动端** | 两个电位器的两端分别接 3V3 和 GND | ✅ 已接入（`chan joy`） |
| A1 / D1 | 摇杆 Y 电位器的**滑动端** | 同上 | ✅ |
| D2 | 压力模块 #1（吹吸）OUT | 吹气对应左键，吸气对应跳跃（长吸用于停用/启用） | ✅（`chan breath`） |
| D3 | 压力模块 #1 SCK | | ✅ |
| D4 | 压力模块 #2（咬合）OUT | 咬合对应 Space | ✅ 已写好，默认关闭（`chan bite 1` 打开） |
| D5 | 压力模块 #2 SCK | | ✅ |
| D6 | 照护者开关，另一端接 GND | 闭合 = 允许启用，断开 = 立即停用 | ⚠️ 代码已写好，`Config.h` 里 `kUseD6Enable=false`，开关接好后改为 true |
| D7 / D8 | 备用咬合微动开关（常开触点接 GND） | 只在气动咬合失败时使用 | ⬜ 还没写 |
| D9 | 摇杆中心按压（可选） | 拓展目标 | ⬜ 还没写 |
| 3V3 | 两个电位器、两个压力模块的 VCC | **唯一的传感器电源** | |
| GND | 所有地线 | | |
| 板载 IMU | 不用接线（内部 I2C） | 头部倾角对应视角 | ✅ |

### 1.2 接线示意

```text
                 ┌──────────── XIAO nRF52840 Sense（戴在头带上，USB-C 接电脑）
 摇杆 X 电位器 ──滑动端── A0      3V3 ──┬── 摇杆两个电位器的一端
 摇杆 Y 电位器 ──滑动端── A1            ├── 压力模块 #1 VCC
 压力 #1 OUT ─────────── D2            └── 压力模块 #2 VCC
 压力 #1 SCK ─────────── D3      GND ──┬── 电位器另一端（×2）
 压力 #2 OUT ─────────── D4            ├── 压力模块 GND（×2）
 压力 #2 SCK ─────────── D5            └── D6 开关另一端
 照护者开关 ──────────── D6
 吹吸软管 → 压力模块 #1 气嘴；咬合密封管 → 压力模块 #2 气嘴（两路气路相互独立）
```

### 1.3 必须遵守

- **只用 3V3，不要接 5V。** 任何模拟输入都不能高于 3.3 V。组员原来的摇杆代码给 Leonardo/UNO 写的是 5 V，在 XIAO 上不适用。
- **D6、D7 不要用作串口。** 这两个脚同时是 UART 的 TX、RX，固件里不能调用 `Serial1.begin()`。
- **口内只放无源件**：咬嘴、杆、食品级软管。电子件、焊点、接头都放在口外。
- **安装方向**：默认是板子平放在头顶，芯片朝上，USB-C 朝后，对应 `mount +Z +X`。装法不同的话，先在测试页上确认轴向，再改 `mount` 设置。
- **IMU 放在嘴前（离嘴有一段距离）时**：转头会让 IMU 绕着头转，额外产生向心/切向加速度，基础模式会把它误当成倾斜。建议在调整页把「融合模式」改成「加速度+角速度融合」（`set fuse 1`），把「力臂前 armx」设成 IMU 到头部转动中心的前向距离（m，默认 0.10），「力臂上 armz」设成 IMU 比转动中心高（+）或低（−）多少（默认 −0.05）。然后做一次「精细校准」（§3.4）。
- 压力模块没接时，OUT 引脚有上拉，固件会在 1 s 后报 `fault_breath_timeout`，不会读出乱码。这时用 `chan breath 0` 关掉这一路即可。

## 2. 控制逻辑（玩的时候发生什么）

| 身体动作 | 游戏操作 | 规则 |
|---|---|---|
| 舌头推杆，前后左右 | W / S / A / D | 推杆期间一直按住；可以斜向组合；松杆就松键 |
| 轻咬 | Space（跳） | 每咬一次跳一次；一直咬着不会连跳 |
| 轻吹 | 鼠标左键（攻击/挖掘） | 默认吹气期间一直按住（最短 60 ms），可以连续挖方块。面板「吹气模式」可改成**吹一下切换**（吹一次按住、再吹一次松开，适合长时间砍树）或**连点**（吹气期间每 600 ms 点一次，适合连续攻击生物） |
| 头部倾斜 | 鼠标视角 | **倾斜超过 6° 并保持 80 ms 才开始转**；回到 4° 以内就停；角度越大转得越快，到 20° 封顶。左右、上下各用哪个角度（侧倾 / 俯仰 / 转头）、是否取反、起转角和灵敏度，都能在面板「调整 → 视角」里分别设置 |
| 吸气 | Space（跳） | 每吸一次跳一次，一直吸着不会连跳；可以和咬合同时使用。吹气期间以及吹气结束后 0.4 s 内不算吸气（用力吹完气压会回弹成负值） |
| 长吸 ≥1.5 s（启用状态下） | 停用 | 立即松开所有按键；时长可在面板里改（`sdis`，0 表示吸气不停用） |
| 长吸 ≥1 s（停用状态下） | 启用 | 进入 3 s 校准；同一口吸气不会先停用再启用 |

状态流程：**停用** →（长吸或点「启用」）→ **校准**：保持静止 3 s，摇杆松开，不吹不吸 → **等待回中**：所有输入回中并保持 300 ms → **启用**。任何传感器断线都会进入**故障**，必须点「确认故障」才能恢复。

**只对 Minecraft 生效**：板子本身无法知道哪个窗口在前台，所以由电脑上的 `bridge.py` 每 250 ms 检测一次前台应用。Minecraft 在前台时，桥会持续告诉板子可以输出；切到其他窗口后，板子在 0.7 s 内停止输出并松开所有按键。桥被关掉也会停止输出。这个功能目前只支持 macOS。

## 3. 使用步骤

### 3.1 第一次准备

1. 拉取最新代码：`git pull`（第一次用 `git clone https://github.com/easonYi991122/MouthMod.git`）。
2. **新 Mac 先运行 `./scripts/setup-macos.sh`**，最后一行显示 `SUMMARY fails=0` 就说明环境装好了，并且已经编译出 `build/ImuBench.uf2`。Apple Silicon 的 Mac 需要先装 Rosetta 2，脚本会提示。也可以让 Codex 按仓库根目录的 `AGENTS.md` 来部署。只想刷固件、不打算改代码的话，可以跳过这一步，直接下载 Release 里的 `ImuBench.uf2`。
3. 烧录固件：用 USB-C 接上板子，**快速双击 RESET**，然后把 `ImuBench.uf2` 拖进 `XIAO-SENSE` 盘。
4. **以后每次更新**（`git pull` 之后）：重新刷 `ImuBench.uf2`（自己编译用 `./scripts/build-firmware.sh`，或者下载最新 Release），再运行 `./scripts/build-float-app.sh` 重建悬浮窗 app。app 里带的是页面和桥的副本，不重建就还是旧面板。

### 3.2 每次使用

1. **双击 `build/MouthMod Float.app`**（`setup-macos.sh` 会生成；也可以把它拖进「应用程序」文件夹）。悬浮窗会自动启动本地桥并连上板子，不需要终端、浏览器，也不用管端口。菜单栏会出现一个手柄图标，里面有「打开完整测试页」（3D 预览和细调参数）和「退出」。
   - 悬浮窗一直置顶，**点它不会抢走 Minecraft 的焦点**：按钮和勾选框随便点，游戏照常接收按键。
   - 点进输入框（参数、命令框）时，键盘会暂时交给悬浮窗；按回车或 Esc 后，键盘自动还给 Minecraft。
   - 关闭悬浮窗等于退出 app，退出时会先停用板子。
   - 不要同时在终端里再运行一个 `bridge.py`，两者会抢同一个串口。
   - **备用方案**（app 打不开，或者是 Windows 电脑时）：在终端运行 `python3 tools/look_demo/bridge.py --http 8766`（8765 被占用时换个端口），然后用 Chrome 或 Edge 打开 `http://localhost:8766/float.html`，点「弹出置顶悬浮窗」。这种方式下点击悬浮窗会把焦点切到 Chrome。
2. 第一次打开时如果提示「无法打开」，在「访达」里右键点 app →「打开」。在本机编译出来的 app 一般不会遇到这个提示。
3. 关掉没接的通道，比如在命令框输入 `chan bite 0`。
4. 首次佩戴时运行一次 `jspan`：先保持松杆，然后在 6 s 内把四个方向各推到舒适的极限。
5. 启用：在停用状态下长吸 1 s，或者点「启用」。然后保持静止 3 s，等状态变成绿色的「启用」。
6. 确认「**真实键鼠输出**」和「**只在 Minecraft 前台时输出**」都已勾选（上电默认都是勾上的）。只想看数据、不想让电脑收到按键时，取消勾选「真实键鼠输出」。
7. 点进 Minecraft 窗口开始玩。悬浮窗会显示「前台 ✓ Minecraft」。
8. 停用方法（任选其一）：长吸 1.5 s；在悬浮窗里点「停用」；关闭悬浮窗；拔线。备用方案下还可以关闭页面，或在终端按 Ctrl+C 停掉桥。

> 悬浮窗 app 设计为可以显示在全屏应用上方，但还没有在全屏的 Minecraft 上实测。如果看不到，就把 Minecraft 改成窗口模式。

### 3.3 悬浮窗显示什么

- **状态色块**：灰色是停用，黄色是校准或等待回中，绿色是启用，红色是故障。
- **前台**：显示当前前台是不是 Minecraft，以及门控是否打开。真实输出已开但 Minecraft 不在前台时，会出现黄色提示。
- **游戏实际收到**：主机真正收到的按键（例如 `W+SPACE`）和左键状态。这是板子确认已经送达的状态，不是推算出来的。
- **视角小图**：圆点表示当前头部倾角误差。外框是起转角 6°，内框是停转角 4°。圆点变绿说明正在转动。旁边列出每秒实际发出的鼠标计数。
- **通道**：摇杆当前对应的键和归一化值；吹吸压力 p；吹、吸、咬三个指示灯。
- **调整页**：点「调整 ▸」展开，分为视角、摇杆、吹气/吸气、配置四组，改完立即生效：
  - **视角**：左右来源和上下来源（侧倾 roll / 俯仰 pitch / 转头 yaw，其中 yaw 为实验功能，会在 `yawtau` 秒内慢慢回零以防漂移）；左右、上下分别取反；kx、ky、左右和上下各自的起转角、确认时间、迟滞。
  - **视角（v0.8.0 新增）**：融合模式（基本互补 / 加速度+角速度融合）、力臂 armx/armz、加速度拒绝 arej；融合模式下实时显示「加速度信任 w」（1 = 完全信任重力，0 = 这一刻只用陀螺）、线加速度和力臂加速度。控制方式：**倾角**（保持倾斜就一直转，原来的方式）、**角速度**（头转多少鼠标走多少，像空中鼠标）、**混合**（两者相加：小幅转头精确瞄准，保持倾斜继续转身）；kgx、kgy 是角速度增益（每转 1° 头移动多少鼠标计数），gdead 是角速度死区（°/s）。
  - **精细校准**：五步引导，只定转动方向，见 §3.4。
  - **摇杆**：左右（A/D）和前后（W/S）分别设置触发、释放阈值；交换 XY；X、Y 分别取反；测量行程。
  - **吹气/吸气**：吹气模式（按住 / 吹一下切换 / 连点）和连点间隔；吹气、吸气阈值；释放延迟；读数取反；吸气跳跃开关；吸气停用时长。
  - **配置**：命令框、刷新；「**保存为默认**」把当前所有参数存到这台电脑上（`~/.mouthmod/profile.txt`），以后每次连上板子都会自动下发；「清除默认」恢复为固件默认值。
  - 板子断电后会恢复固件默认值，所以调好的参数记得「保存为默认」。
- **精简页**（常驻）：状态、前台、游戏实际收到的按键、视角小图、通道、启用/停用、两个输出开关、「精细校准 开/关」、提示和最近 4 条事件。

### 3.4 精细校准（v0.8.1 修订）

基础校准（点「启用」后静止 3 s）测陀螺零偏，并把当时的姿势当成中立位。精细校准只负责一件事：**认出使用者自己的「左右转」和「上下转」是绕哪个方向转的**（比如左右主要是转头，带一点侧倾）。它**不决定**转多快、从多少度开始转：起转角、封顶、增益、迟滞仍然在「调整 → 视角」里按「度」调节，和不做精细校准时一样。

1. 先点一次「启用」完成基础校准（静止 3 s）。没做过基础校准时点「记录」会提示先校准，因为转头角要靠陀螺零偏。正在启用时点「记录」，面板会先自动停用。
2. 打开「调整 → 精细校准」，按顺序做五步，每步摆好姿势、**保持静止半秒**，点「记录」：**中立 → 左转 → 右转 → 低头 → 抬头**。动作做明显一点（离中立 10° 以上更稳），不必到极限。提示「动了，重来」就重新记录这一步。
3. 第五步记完会**自动启用**精细校准，状态行显示「左右轴」「上下轴」由哪些动作组成（如「转头 0.99」）。左右、上下的方向由你记录的姿势决定：向左转就往左，向右转就往右，不用再勾取反。
4. 之后每次点「启用」，基础校准只把**中立位**换成当时的姿势，转轴沿用上次精细校准的结果，不用重做五步。换了坐姿、IMU 位置没动时都这样处理；IMU 重新安装或改了 `mount` 才需要重做。
5. 点「保存为默认」，中立位和四个相对姿势会一起保存（`fcal val n …` 和 `fcal rel l|r|d|u …`），下次连上板子自动恢复。

报错说明：「左右姿势无效」（上下同理）表示左转、右转没有分在中立两侧，或离中立不到 3°；「左右和上下的转动方向太接近」表示低头、抬头和左右转几乎是同一个动作；重新记录幅度更明显、更「纯」的姿势即可。

## 4. 指令速查

| 命令 | 作用 |
|---|---|
| `arm` / `x`（或 `disarm`）/ `ack` | 启用 / 停用 / 确认故障 |
| `hid 0\|1` | 关闭 / 打开真实键鼠输出（上电默认打开；关闭页面只会停用，不会关掉它） |
| `fgate 0\|1` | 关闭 / 打开前台门控；悬浮窗连接上时会自动打开 |
| `chan joy\|breath\|bite 0\|1` | 关闭 / 打开某个通道 |
| `jspan` | 测量每个人的摇杆舒适行程（停用状态下才能用） |
| `set dead 6` / `set deadx 6` / `set deady 6` / `set confirm 80` | 视角起转角（两轴 / 仅左右 / 仅上下，°）；起转确认时间（ms） |
| `set hsrc 0\|1\|2` / `set vsrc 0\|1\|2` / `set invx 1` / `set invy 1` / `set yawtau 20` | 左右、上下视角的来源（0 侧倾 roll、1 俯仰 pitch、2 转头 yaw）；取反；yaw 回零时间（s，0 不回零） |
| `set kx 40` / `set ky 30` | 左右 / 上下视角增益（计数/秒/度） |
| `set jon 0.12` / `set joff 0.08`（两轴）/ `set jonx` `jony` `joffx` `joffy` | 摇杆触发 / 释放阈值（占舒适行程的比例），可按轴分别设置 |
| `set jswap 1` / `set jinvx 1` / `set jinvy 1` | 摇杆交换 XY、X 取反、Y 取反 |
| `set pmode 0\|1\|2` / `set prep 600` | 吹气模式：0 按住、1 吹一下切换、2 连点；连点间隔（ms） |
| `set sjump 0\|1` / `set sdis 1500` | 吸气跳跃开关；吸气停用所需时长（ms，0 = 吸气不停用） |
| `set fuse 0\|1` / `set armx 0.10` / `set armz -0.05` / `set arej 0.15` | 融合模式（0 基本互补、1 加速度+角速度融合）；力臂前 / 上（m）；加速度拒绝阈值（g） |
| `set lmode 0\|1\|2` / `set kgx 8` / `set kgy 8` / `set gdead 3` | 控制方式（0 倾角、1 角速度、2 混合）；角速度增益（计数/°）；角速度死区（°/s） |
| `fcal n\|l\|r\|d\|u` / `fcal on` / `fcal off` / `fcal clear` | 精细校准：记录中立 / 左转 / 右转 / 低头 / 抬头（五步齐了自动启用）；启用；关闭；清除 |
| `set bsign -1` | 吹气读数是负数时翻转符号 |
| `set bon 120000` / `set boff 50000` / `set son` / `set soff` / `set brel 250` / `set slock 400` | 吹气、吸气阈值（counts）；吹气释放延迟（ms）；吹气后多久内不算吸气（ms） |
| `act w 2000` / `tap jump` / `tap use` | 不接传感器，直接模拟动作（启用状态下才能用） |
| `turn 600 100` | 精确发出 600 个鼠标计数，用来测游戏灵敏度和指针加速 |
| `mount +Z +X` | 设置安装方向（朝上轴、朝前轴） |
| `get` | 打印身份、参数、通道参数和校准结果 |

## 5. 常见问题

| 现象 | 先查这里 |
|---|---|
| 一直停在「校准中」或回到停用 | 日志里的 `fail_motion` 表示动了；`fail_joystick_center` 表示摇杆没松开；`fail_breath_baseline` 表示压力模块没有读数 |
| 视角完全不动、游戏没反应 | 先看状态色块：**红色「故障」**时什么都不输出，悬浮窗会显示原因，排除后点「确认故障」再启用；**绿色「启用」但提示「真实键鼠输出」没勾**时，小图会动但游戏收不到（关闭或刷新页面会自动关掉真实输出） |
| 一直「等待回中」 | 头、摇杆、吹吸要同时回中并保持 300 ms。看悬浮窗里哪个指示灯还亮着 |
| 头稍微一动视角就转 | 调大起转角 `set dead 8`（或只调一个轴：`deadx` / `deady`），或者调长确认时间 `set confirm 120` |
| 视角方向反了 / 左右和上下对调了 | 在「调整 → 视角」里改左右来源、上下来源，或勾选取反 |
| 吹气不能「一直砍」 | 看悬浮窗「左键」：吹气中途变成 ○，说明气压掉到释放阈值以下，调低 `boff` 或调长 `brel`；一直是 ●，那是游戏行为：按住左键能连续挖方块，但不会连续攻击生物，改用「连点」模式；长时间砍树可用「吹一下切换」 |
| 一吸气就停用了 | 吸气超过 `sdis`（默认 1.5 s）才会停用；仍误停用就在面板把「吸气停用」调长，或设为 0（这时用按钮或开关停用） |
| IMU 在嘴前，转头时视角乱跳、上下也跟着动 | 改用融合模式 `set fuse 1` 并设好 `armx`/`armz`；看「加速度信任 w」，转头时降到 0 附近说明在拒绝干扰加速度。仍然串轴就做精细校准，或者把控制方式改成「混合」 |
| 坐姿不正，一启用就开始转 | 在舒服的位置点「启用」并静止 3 s：中立位就是那时的姿势；精细校准开着时转轴沿用，只换中立位（§3.4） |
| 不管往哪边转头，鼠标都往同一边 | v0.8.0 的转头角按板子 Z 轴算，IMU 立着装时测不到转头，只剩向心加速度干扰。升级到 v0.8.1（转头角改为绕重力竖直方向）并做一次精细校准；仍不对就在测试页确认 `mount` |
| 要偏很大角度才转 | 调小 `dead`，或者调大 `kx`、`ky` |
| 悬浮窗显示「✗ 其他应用」，游戏没反应 | 点回 Minecraft 窗口；或者临时取消勾选「只在 Minecraft 前台时输出」 |
| 吹气时反而停用了 | 每次吹气都停用：吹气读成了吸气，执行 `set bsign -1`。只在用力吹完之后停用：回弹超过了 0.4 s，执行 `set slock 700` |
| 轻吹没反应、用力吹才有 | 实测静止噪声约 ±300 counts，轻吹约 100000～150000，用力吹可达 3000000；可以把阈值降到 `set bon 60000`、`set boff 25000` |
| 报 `fault_breath_timeout` | 压力模块没接或接触不良；没接的话用 `chan breath 0` |
| 桥打不开串口 / 悬浮窗显示「本地桥已退出」 | 串口同时只能被一个程序打开：悬浮窗 app、终端里的 `bridge.py`、Arduino 串口监视器、Chrome 网页串口，只能留一个。关掉多余的，再从菜单栏图标退出并重新打开悬浮窗 |
| Windows 电脑 | 桥依赖 macOS/Linux 的串口接口，前台检测也只支持 macOS。Windows 上只能用主页面的 Web Serial 模式，**没有前台门控和悬浮窗** |
