# MouthMod 接线与使用说明（v0.6.1）

2026-10-20 · 固件 `MouthMod-ImuBench 0.6.1` · 板子 Seeed XIAO nRF52840 Sense

一句话概括：所有传感器都接到同一块 XIAO 上，这块板通过 USB 直接充当键盘和鼠标。电脑上运行一个本地桥 `bridge.py`，负责显示状态、调参，并且只在 Minecraft 位于前台时放行输出。

> 状态说明：本文所有功能都已编译，并通过了主机端测试。前台门控和悬浮窗在模拟板上跑通了。**接上真实传感器后的效果、在 Minecraft 里的实际表现，都还没有验证**，以今晚的实测为准（测试表见 [minecraft-education.md](minecraft-education.md) 第 5 节）。

## 1. 接线

### 1.1 引脚表（规格冻结，不要改）

| XIAO 引脚 | 接什么 | 说明 | 固件现状 |
|---|---|---|---|
| A0 / D0 | 摇杆 X 电位器的**滑动端** | 两个电位器的两端分别接 3V3 和 GND | ✅ 已接入（`chan joy`） |
| A1 / D1 | 摇杆 Y 电位器的**滑动端** | 同上 | ✅ |
| D2 | 压力模块 #1（吹吸）OUT | 吹气对应左键，吸气用于停用/启用 | ✅（`chan breath`） |
| D3 | 压力模块 #1 SCK | | ✅ |
| D4 | 压力模块 #2（咬合）OUT | 咬合对应 Space | ✅ 已写好，默认关闭（`chan bite 1` 打开） |
| D5 | 压力模块 #2 SCK | | ✅ |
| D6 | 照护者开关，另一端接 GND | 闭合 = 允许启用，断开 = 立即停用 | ⚠️ 代码已写好，`Config.h` 里 `kUseD6Enable=false`，开关接好后改为 true |
| D7 / D8 | 备用咬合微动开关（常开触点接 GND） | 只在气动咬合失败时使用 | ⬜ 还没写 |
| D9 | 摇杆中心按压（可选） | 拓展目标 | ⬜ 还没写 |
| 3V3 | 两个电位器、两个压力模块的 VCC | **唯一的传感器电源** | |
| GND | 所有地线 | | |
| 板载 IMU | 不用接线（内部 I2C） | 头部倾角对应视角 | ✅ |

### 1.2 接线示意

```text
                 ┌──────────── XIAO nRF52840 Sense（戴在头带上，USB-C 接电脑）
 摇杆 X 电位器 ──滑动端── A0      3V3 ──┬── 摇杆两个电位器的一端
 摇杆 Y 电位器 ──滑动端── A1            ├── 压力模块 #1 VCC
 压力 #1 OUT ─────────── D2            └── 压力模块 #2 VCC
 压力 #1 SCK ─────────── D3      GND ──┬── 电位器另一端（×2）
 压力 #2 OUT ─────────── D4            ├── 压力模块 GND（×2）
 压力 #2 SCK ─────────── D5            └── D6 开关另一端
 照护者开关 ──────────── D6
 吹吸软管 → 压力模块 #1 气嘴；咬合密封管 → 压力模块 #2 气嘴（两路气路相互独立）
```

### 1.3 必须遵守

- **只用 3V3，不要接 5V。** 任何模拟输入都不能高于 3.3 V。组员原来的摇杆代码给 Leonardo/UNO 写的是 5 V，在 XIAO 上不适用。
- **D6、D7 不要用作串口。** 这两个脚同时是 UART 的 TX、RX，固件里不能调用 `Serial1.begin()`。
- **口内只放无源件**：咬嘴、杆、食品级软管。电子件、焊点、接头都放在口外。
- **安装方向**：默认是板子平放在头顶，芯片朝上，USB-C 朝后，对应 `mount +Z +X`。装法不同的话，先在测试页上确认轴向，再改 `mount` 设置。
- 压力模块没接时，OUT 引脚有上拉，固件会在 1 s 后报 `fault_breath_timeout`，不会读出乱码。这时用 `chan breath 0` 关掉这一路即可。

## 2. 控制逻辑（玩的时候发生什么）

| 身体动作 | 游戏操作 | 规则 |
|---|---|---|
| 舌头推杆，前后左右 | W / S / A / D | 推杆期间一直按住；可以斜向组合；松杆就松键 |
| 轻咬 | Space（跳） | 每咬一次跳一次；一直咬着不会连跳 |
| 轻吹 | 鼠标左键（攻击/挖掘） | 吹气期间一直按住，最短 60 ms；按住可以连续挖方块 |
| 头部倾斜 | 鼠标视角 | **倾斜超过 6° 并保持 80 ms 才开始转**；回到 4° 以内就停；角度越大转得越快，到 20° 封顶 |
| 短吸 ≥150 ms | 停用 | 立即松开所有按键。吹气期间以及吹气结束后 0.4 s 内不算吸气（用力吹完气压会回弹成负值，以前会被误判为吸气而停用） |
| 长吸 ≥1 s（停用状态下） | 启用 | 进入 3 s 校准；同一口吸气不会先停用再启用 |

状态流程：**停用** →（长吸或点「启用」）→ **校准**：保持静止 3 s，摇杆松开，不吹不吸 → **等待回中**：所有输入回中并保持 300 ms → **启用**。任何传感器断线都会进入**故障**，必须点「确认故障」才能恢复。

**只对 Minecraft 生效**：板子本身无法知道哪个窗口在前台，所以由电脑上的 `bridge.py` 每 250 ms 检测一次前台应用。Minecraft 在前台时，桥会持续告诉板子可以输出；切到其他窗口后，板子在 0.7 s 内停止输出并松开所有按键。桥被关掉也会停止输出。这个功能目前只支持 macOS。

## 3. 使用步骤

### 3.1 第一次准备

1. 拉取最新代码：`git pull`（第一次用 `git clone https://github.com/easonYi991122/MouthMod.git`）。
2. **新 Mac 先运行 `./scripts/setup-macos.sh`**，最后一行显示 `SUMMARY fails=0` 就说明环境装好了，并且已经编译出 `build/ImuBench.uf2`。Apple Silicon 的 Mac 需要先装 Rosetta 2，脚本会提示。也可以让 Codex 按仓库根目录的 `AGENTS.md` 来部署。只想刷固件、不打算改代码的话，可以跳过这一步，直接下载 Release 里的 `ImuBench.uf2`。
3. 烧录固件：用 USB-C 接上板子，**快速双击 RESET**，然后把 `ImuBench.uf2` 拖进 `XIAO-SENSE` 盘。

### 3.2 每次使用

1. 在仓库根目录启动本地桥：
   ```bash
   python3 tools/look_demo/bridge.py
   ```
   如果提示端口被占用（这台 Mac 上 8765 已经被别的程序占了），改用：
   ```bash
   python3 tools/look_demo/bridge.py --http 8766
   ```
2. 在 **Chrome 或 Edge** 中打开 `http://localhost:8766/float.html`，点「**弹出置顶悬浮窗**」，悬浮窗会一直显示在 Minecraft 上方。需要 3D 预览或细调参数时，打开主页面 `http://localhost:8766`。
3. 关掉没接的通道，比如在命令框输入 `chan bite 0`。
4. 首次佩戴时运行一次 `jspan`：先保持松杆，然后在 6 s 内把四个方向各推到舒适的极限。
5. 启用：在停用状态下长吸 1 s，或者点「启用」。然后保持静止 3 s，等状态变成绿色的「启用」。
6. 确认「**真实键鼠输出**」和「**只在 Minecraft 前台时输出**」都已勾选（上电默认都是勾上的）。只想看数据、不想让电脑收到按键时，取消勾选「真实键鼠输出」。
7. 点进 Minecraft 窗口开始玩。悬浮窗会显示「前台 ✓ Minecraft」。
8. 停用方法（任选其一）：短吸；在悬浮窗里按 Esc 或点「停用」；关闭页面；按 Ctrl+C 停掉桥；拔线。

> 如果在全屏的 Minecraft 上方看不到悬浮窗，就把 Minecraft 改成窗口模式。这一点还没有实测。

### 3.3 悬浮窗显示什么

- **状态色块**：灰色是停用，黄色是校准或等待回中，绿色是启用，红色是故障。
- **前台**：显示当前前台是不是 Minecraft，以及门控是否打开。真实输出已开但 Minecraft 不在前台时，会出现黄色提示。
- **游戏实际收到**：主机真正收到的按键（例如 `W+SPACE`）和左键状态。这是板子确认已经送达的状态，不是推算出来的。
- **视角小图**：圆点表示当前头部倾角误差。外框是起转角 6°，内框是停转角 4°。圆点变绿说明正在转动。旁边列出每秒实际发出的鼠标计数。
- **通道**：摇杆当前对应的键和归一化值；吹吸压力 p；吹、吸、咬三个指示灯。
- **可调参数**：起转角、确认时间、kx、ky，改完立即生效。
- **命令框**：可以输入下面任何一条命令。最近 6 条事件和回执显示在最下面。

## 4. 指令速查

| 命令 | 作用 |
|---|---|
| `arm` / `x`（或 `disarm`）/ `ack` | 启用 / 停用 / 确认故障 |
| `hid 0\|1` | 关闭 / 打开真实键鼠输出（上电默认打开；关闭页面只会停用，不会关掉它） |
| `fgate 0\|1` | 关闭 / 打开前台门控；悬浮窗连接上时会自动打开 |
| `chan joy\|breath\|bite 0\|1` | 关闭 / 打开某个通道 |
| `jspan` | 测量每个人的摇杆舒适行程（停用状态下才能用） |
| `set dead 6` / `set confirm 80` | 视角起转角（°）/ 起转确认时间（ms） |
| `set kx 40` / `set ky 30` | 左右 / 上下视角增益（计数/秒/度） |
| `set jon 0.12` / `set joff 0.08` | 摇杆触发 / 释放阈值（占舒适行程的比例） |
| `set bsign -1` | 吹气读数是负数时翻转符号 |
| `set bon 120000` / `set boff 50000` / `set son` / `set soff` / `set brel 250` / `set slock 400` | 吹气、吸气阈值（counts）；吹气释放延迟（ms）；吹气后多久内不算吸气（ms） |
| `act w 2000` / `tap jump` / `tap use` | 不接传感器，直接模拟动作（启用状态下才能用） |
| `turn 600 100` | 精确发出 600 个鼠标计数，用来测游戏灵敏度和指针加速 |
| `mount +Z +X` | 设置安装方向（朝上轴、朝前轴） |
| `get` | 打印身份、参数、通道参数和校准结果 |

## 5. 常见问题

| 现象 | 先查这里 |
|---|---|
| 一直停在「校准中」或回到停用 | 日志里的 `fail_motion` 表示动了；`fail_joystick_center` 表示摇杆没松开；`fail_breath_baseline` 表示压力模块没有读数 |
| 视角完全不动、游戏没反应 | 先看状态色块：**红色「故障」**时什么都不输出，悬浮窗会显示原因，排除后点「确认故障」再启用；**绿色「启用」但提示「真实键鼠输出」没勾**时，小图会动但游戏收不到（关闭或刷新页面会自动关掉真实输出） |
| 一直「等待回中」 | 头、摇杆、吹吸要同时回中并保持 300 ms。看悬浮窗里哪个指示灯还亮着 |
| 头稍微一动视角就转 | 调大起转角 `set dead 8`，或者调长确认时间 `set confirm 120` |
| 要偏很大角度才转 | 调小 `dead`，或者调大 `kx`、`ky` |
| 悬浮窗显示「✗ 其他应用」，游戏没反应 | 点回 Minecraft 窗口；或者临时取消勾选「只在 Minecraft 前台时输出」 |
| 吹气时反而停用了 | 每次吹气都停用：吹气读成了吸气，执行 `set bsign -1`。只在用力吹完之后停用：回弹超过了 0.4 s，执行 `set slock 700` |
| 轻吹没反应、用力吹才有 | 实测静止噪声约 ±300 counts，轻吹约 100000～150000，用力吹可达 3000000；可以把阈值降到 `set bon 60000`、`set boff 25000` |
| 报 `fault_breath_timeout` | 压力模块没接或接触不良；没接的话用 `chan breath 0` |
| 桥打不开串口 | Arduino 串口监视器、Chrome 网页串口、桥三者同时只能有一个打开串口 |
| Windows 电脑 | 桥依赖 macOS/Linux 的串口接口，前台检测也只支持 macOS。Windows 上只能用主页面的 Web Serial 模式，**没有前台门控和悬浮窗** |
