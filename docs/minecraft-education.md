# Minecraft Education 适配与今晚整合

固件 `MouthMod-ImuBench 0.5.0` · 2026-10-19 · 本文所有游戏内结果都**还没测**，要在今晚实机测试时填写。

## 1. 结论：保持键鼠 HID，不改成手柄

保持现在的思路：nRF52840 用 TinyUSB 模拟 USB 键盘和鼠标，直接对应 Minecraft 的默认键位。不要改成「手柄 → 游戏指令」。

| 依据 | 说明 |
|---|---|
| 规格冻结 | 交接指南 §c 和 [E] §4–5 写明「USB 键盘＋鼠标；W/A/S/D 可组合并保持；咬合 Space；吹气右键；吸气停用」是冻结项。提案说明这块板承担的是赛题中 Arduino Leonardo 的键鼠角色，评估的 7 个动作也是按键名定义的 |
| 平台支持 | Microsoft 官方的 Minecraft Education 上手教程只介绍了键鼠和触屏操作。我们没有找到它在 Mac 上支持手柄的官方说明。nRF52 用 TinyUSB 模拟出来的是通用 HID 手柄，不是 Xbox（XInput）手柄，游戏能不能识别没法保证 |
| 控制效果 | 头部视角已经按「倾角 → 速度」做好了死区、迟滞和饱和。手柄摇杆在游戏里还会再叠加一层游戏自己的死区和加速曲线，两层曲线叠在一起很难调 |
| 时间 | 今晚就要整合。改走手柄需要重写 HID 描述符、状态机里的释放逻辑和全部测试，而且游戏能不能识别要到最后才知道 |

手柄唯一的优势是行走可以有模拟量的快慢，但规格要求的是 W/A/S/D 按住或松开，不需要这一点。

> 「nRF → Arduino」的意思是：在 nRF52840 上跑 Arduino 代码，由这块板直接作为 USB 键鼠。不需要再串一块 Leonardo。交接指南也写明，Leonardo 的 `Keyboard.h`／`Mouse.h` 程序不能直接搬过来用。

## 2. 动作 → 按键（冻结映射）

| 身体动作 | 通道 | Minecraft Education 默认操作 | HID 码 | 发送规则（`logic/GameInput`） |
|---|---|---|---|---|
| 舌杆前/后/左/右 | 摇杆 | W / S / A / D | 0x1A / 0x16 / 0x04 / 0x07 | 按住期间保持；可以斜向组合；前后同时为真时都不发 |
| 轻咬 | 压力 #2 | Space（跳） | 0x2C | 每次上升沿发**一次**点按，至少按住 60 ms。一直咬住不会连发，松开后再咬才会再次触发 |
| 轻吹 | 压力 #1 | 鼠标**左键**（攻击/挖掘，D29） | 按钮位 0x01 | 默认吹气期间一直按住，最短 60 ms；`pmode` 1 = 吹一下切换，2 = 连点（`prep` ms，D35）；按下和松开两个报告都必须被端点接受 |
| 吸气 | 压力 #1 | Space（跳，D34） | 0x2C | 每次吸气上升沿点按一次，与咬合合并；吹气后 `slock` 内不算吸气 |
| 头部倾斜 | IMU | 鼠标移动（视角） | 相对 dx/dy | 每个鼠标报告都带上当前按钮状态，所以转头不会把左键松掉 |
| 长吸 ≥1.5 s（`sdis`）/ D6 断开 | 压力 #1 / 开关 | （停用） | — | 立即释放所有按键和按钮，不等 60 ms |

键码集中定义在 `src/logic/GameInput.h` 的 `mc::` 命名空间里。如果游戏里改了键位，只需要改这一处。

### 为什么要有 60 ms 最短按住

游戏是按帧或按 tick 读取按键状态的，Minecraft 的 tick 是 50 ms。如果按下和松开相隔只有 2 ms，游戏很可能根本看不到这次按键。60 ms 是暂定值（decisions D16），以实测为准：在游戏里连按 20 次 `tap jump`，跳起的次数应该正好是 20 次。

## 3. 组员代码的移植（已接入 ImuBench）

组员的两份代码已经移植进 `firmware/ImuBench`，和头部视角在同一个 100 Hz 循环里运行。所有通道先汇总成 `GameIntent`，再由 `GameInput` 统一发送：

```cpp
intent.forward = gJoy.forward();    // 摇杆 → W/A/S/D
intent.use     = gBreath.active();  // 吹气 → 左键（D29）
intent.jump    = gBite.active();    // 咬合 → Space（目前默认关闭）
gGame.update(t, intent, state == ACTIVE);
```

**整合时请不要在各自的代码里直接调用 `Keyboard.press` 或 `Mouse.press`**。分开调用会出现两种情况：跳一下就把 W 松掉，或者鼠标一动右键就松开。交接指南 §HID 明确禁止这两种情况。

### 3.1 原代码为什么不能直接用

| 原代码 | 问题 | 移植后 |
|---|---|---|
| 吹气：`#include "USB.h"`、`USBHIDMouse` | 这是 **ESP32-S2/S3 Arduino core** 的接口，不是 STM32 的，也不是我们的板子用的接口。在 Seeed nRF52 core 上无法编译 | 改用板包自带的 TinyUSB 复合 HID（`HidOutput`） |
| 摇杆：XIAO 走「串口 → Python `pynput` → 模拟按键」 | 按键是电脑上的 Python 发出的，而不是板子作为 USB 键盘发出的。需要 macOS「辅助功能」权限，还要用 F8 手动启用，安全状态机管不到这些按键 | 板子直接作为 USB 键盘输出，按键受 DISARMED/ACTIVE 状态控制 |
| 两份都在 `setup()` 里 `delay()` 阻塞校准；吹气校准失败就 `while(true)` 死循环 | 卡住时 USB 不释放按键，主循环也不跑 | 校准改为不阻塞，放在「启用 → 静止 3 s」的窗口里一起完成；失败就停用，并报告原因 |
| 吹气：`magnitude = abs(delta)` | **吸气也会触发点击**。但规格里吸气的作用是停用 | 改为带符号：吹气为正，吸气为负。吸气达到 150 ms 就停用；**v0.7.0 起吸气改为跳跃**，吸住 1.5 s 才停用（D34） |
| 吹气：整次读取都包在 `noInterrupts()` … `interrupts()` 里 | 读完后会无条件打开中断。交接指南要求每个 SCK 高电平单独做短临界区，并恢复进入前的中断状态 | 已按要求实现（`hardware/Hx710b`） |
| 吹气：**左键**＋自动连击（600 ms 一次） | 规格冻结的映射是「轻吹 → **右键**」（使用/放置），比赛要求的也是右键 | v0.4–0.6.0 用的是右键；**v0.6.1 起按组内决定改为左键**（D29），吹气期间一直按住。要改回右键，只需把 `GameInput.h` 里的 `mc::kButtonPuff` 改为 0x02；v0.7.0 起可在面板选「连点」模式恢复自动连击（`pmode 2`，D35） |
| 摇杆：10 位 ADC，绝对阈值 120/80 | 规格要求 12 位、`AR_INTERNAL`；阈值以松杆为零点，正负两侧分别按「舒适行程」归一化，触发 0.12、释放 0.08 | 已按规格实现；新增 `jspan` 命令，按个人测量舒适行程 |

保留不变的部分：引脚（A0/A1，D2/D3）；HX710B 27 个脉冲（40 Hz 差分）；吹气阈值 120000/50000 counts 和 250 ms 释放延迟；摇杆的方向约定（Y 读数变小 = W，X 读数变小 = A）和 swap/invert 选项。

> 换算参考：原摇杆阈值 120 是 10 位读数，在 XIAO 默认 3.6 V 量程下约为 0.42 V，相当于半程（1.65 V）的 0.26。规格起点 0.12 比它灵敏一倍多。如果实测容易误触发，先用 `jspan` 测出舒适行程；仍然误触发，再用 `set jon 0.2` 和 `set joff 0.14` 调高阈值。

### 3.2 没有接传感器时

同一个固件，如果某个传感器没有接，用 `chan` 命令关掉对应通道，否则会报 FAULT 或进不了 ACTIVE：

```
chan joy 0
chan breath 0
chan bite 1     # 咬合模块接好后再打开（默认关闭，组员还没有给出咬合代码）
```

HX710B 的 OUT 引脚开了上拉。模块没接时，读数始终是「未就绪」，1 s 后报 `fault_breath_timeout`，不会读出乱码。

## 4. 游戏内设置（每台电脑测一次，记下来）

| 设置 | 建议 | 原因 |
|---|---|---|
| 键位 | 保持默认 | 映射表按默认键位写 |
| 自动跳跃（设置 → 控制/键盘和鼠标里的 Auto Jump） | 评估时**关闭**，演示时可以讨论 | 打开后，碰到一格高的方块会自动跳，「跳」这个动作的触发次数就没法统计了 |
| 鼠标灵敏度 | 先放在中间，按第 5 节测出度/计数后再定，记下数值 | 提案要求练习时确定，比赛时不再改 |
| 反转 Y 轴 | 关闭。方向如果反了，用固件的 `invy` 修 | 避免两处同时反转 |
| 测试世界 | 创造模式、超平坦，地上放一排对齐的方块当参照物 | 便于观察转角和跳跃 |

**macOS 的「指针加速」**：如果游戏读的是系统光标位移，而不是原始输入，macOS 的指针加速会让「慢转」和「快转」走的角度不一样。下面第 5 节的 B 项就是测这一点的。如果确实不一致，需要你们自己在「系统设置 → 鼠标 → 高级」里关闭指针加速，我不会去改系统设置。

## 5. 今晚的实机测试步骤

准备：
- 先把 `build/ImuBench.uf2` 烧进板子：双击 RESET，然后拖进 XIAO-SENSE 盘。烧录前先停掉占用串口的桥。
- 运行 `python3 tools/look_demo/bridge.py`，打开 http://localhost:8765。
- 没接的传感器先用 `chan` 关掉（见 3.2）。摇杆先跑一次 `jspan`：发出命令后保持松杆，然后 6 s 内把四个方向各推到舒适的极限。
- 点「启用」，保持静止 3 s（头不动，摇杆松开，不吹不吸），等状态变成 ACTIVE。如果校准失败，日志会给出原因：`fail_joystick_center`（校准时摇杆动了）或 `fail_breath_baseline`（压力没有读数）。
- 确认「真实键鼠输出」已勾选（v0.6.1 起上电默认开启，`hid 1`）。

页面日志下方新加了**命令框**，可以直接输入下面的命令。日志里的 `游戏输出: keys=W+SPACE left=1` 显示的是主机实际收到的按键状态。

> 游戏窗口在前台时，页面上的 Esc/X 不起作用。可以随时用这些方法停用：关闭页面、Ctrl+C 停掉桥、拔线，三者都会触发 DTR 停用。用带时长的命令（例如 `act w 2000`）的话，到时间按键会自动松开，比较安全。

| # | 测什么 | 操作（在命令框里输入，然后马上点回游戏窗口） | 通过标准 | 结果 |
|---|---|---|---|---|
| A1 | 行走 | `act w 2000`，然后 s/a/d 各测一次 | 朝对应方向走 2 s 后停下 | |
| A2 | 斜走 + 跳 | `act w 3000` 后立刻 `tap jump` | 边走边跳，跳完继续往前走（W 没被松掉） | |
| A3 | 单次跳 | `tap jump` ×20 | 正好跳 20 次，没有漏跳也没有连跳 | |
| A4 | 咬住不连发 | `act jump 1`，等 3 s，再 `act jump 0` | 只跳一次 | |
| A5 | 左键单击 | 对着方块，`tap use` | 敲一下方块（或攻击一下） | |
| A6 | 左键按住 + 转头 | `act use 2000` 期间转头 | 日志中 left 一直为 1，没有中途松开 | |
| A7 | 停用释放 | `act w 1` 走动时，关闭页面 / 拔线 / `x` | 立刻停下，没有卡键 | |
| E1 | 摇杆读数 | 页面「链路状态」→ 摇杆，四个方向各推一次 | 松杆时归一化值约为 0，推过 0.12 时出现对应的键；方向反了用 `set jinvx 1`、`set jinvy 1` 或 `set jswap 1` 修正 | |
| E2 | 摇杆 + 跳 + 视角 | 推着 W 走，同时 `tap jump` 并转头 | W 一直保持，跳和视角都正常 | |
| E3 | 吹气符号 | 页面「吹吸 #1」，轻吹 | p 为正，吹 = 1。如果 p 为负，用 `set bsign -1` 修正，并记录下来 | |
| E4 | 吹气 → 左键 | 对着方块持续吹气 | 方块被挖掉；吹完 250 ms 内松开 | |
| E5 | 吸气跳跃 / 长吸停用 | ACTIVE 状态下短吸一下；再吸住 1.5 s | 短吸跳一次；长吸后日志出现 `sip_disarm`，所有按键松开（D34） | |
| E5b | 吹气模式 | `set pmode 1` 吹一下再吹一下；`set pmode 2` 持续吹气打生物 | 切换模式下左键保持到第二次吹气；连点模式下每 600 ms 攻击一次（D35） | |
| E6 | 吸气不误点 | 吸气 | 不会触发左键（原代码会触发） | |
| E6b | 吹气回弹不停用 | 用力吹 1 s 后松口 | 不会出现 `sip_disarm`，仍是启用状态（D31） | |
| E7 | 拔掉压力模块 | 运行中断开 D2 | 约 0.25 s 后报 `fault_breath_timeout`，并释放所有按键 | |
| E8 | 长吸启用 | DISARMED 状态、页面开着，吸气保持 1 s 以上 | 日志出现 `sip_arm`，进入校准；松开吸气、保持静止，进入 ACTIVE | |
| E9 | 连吸不重新启用 | ACTIVE 状态下一直吸气 3 s | 1.5 s 后停用；继续吸也**不会**重新启用；松开后再长吸才启用 | |
| B | 鼠标线性（指针加速） | 准星对准远处的参照方块：`turn 600 100`（慢），然后 `turn -600 3000`（快） | 准星回到原来的参照点。回不去说明有加速，要关掉指针加速 | |
| C | 度/计数 | `turn N 400`，调整 N，直到正好转一整圈 360° | 记录灵敏度设置和 N；度/计数 = 360 / N | |
| E10 | 视角起转区间 | ACTIVE 状态下轻微晃头（<6°，或者超过 6° 但不到 80 ms） | 视角不动；稳定倾斜超过 6° 后从慢速开始转 | |
| E11 | 只对 Minecraft 生效 | hid 1 时按住摇杆，同时切到别的窗口 | 0.7 s 内松键、停转，悬浮窗显示「✗ 其他应用」；切回 Minecraft 后恢复 | |
| D | 选 k | 按 C 的结果换算：视角速度（°/s）= k × 倾角 × (360/N) | 低头/侧倾 10° 时转速合适；把 k 写进 Config.h 和记录 | |

C 项的结果可以直接把测试页的「Java 灵敏度公式」换成实测的度/计数，之后在页面上对比 k 才有实际意义。

## 6. 已改动、未验证

- 已完成：主机端测试 38 组全部通过（IMU 19 组、GameInput 9 组、摇杆/压力/长吸 10 组）。固件编译通过，86.3 KB，我们自己的代码没有警告。测试页在浏览器里显示通道数据正常。
- **都还没在实板或游戏里验证**：
  - 真实按键是否送达，60 ms 是否够用；
  - 键盘和鼠标轮流发送时的延迟；
  - USB 重新枚举后是否保持 DISARMED；
  - HX710B 的实际脉宽（应该用逻辑分析仪测）；
  - 吹气符号、吸气阈值（目前和吹气阈值对称，还是暂定值）；
  - 摇杆的舒适行程。
- v0.5.0 新增：长吸启用（D25），看门狗模块和复位原因上报（D26，默认关闭）。这两项只有主机测试，没有实测。
- 还没做的：D6 照护者开关（代码里已有，`kUseD6Enable` 默认关闭，等开关接好再打开）；咬合的硬件代码。
- 单文件版 `ImuLookMini` 只有视角功能。整合时以 `ImuBench` 为准。
